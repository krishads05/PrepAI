Deadlock avoidance requires that the system has additional information about resource requests. The Banker's algorithm uses Available, Max, Allocation and Need matrices. The safety algorithm checks whether the system is in a safe state by finding a safe sequence of processes such that each process's remaining need can be satisfied. The resource-request algorithm checks whether a request can be granted safely.
Deadlock detection uses a wait-for graph for single instance resources, and a detection algorithm similar to the safety algorithm for multiple instances. Recovery from deadlock can be done by process termination or resource preemption, choosing a victim and handling rollback and starvation.
CPU scheduling selects a process from the ready queue. Criteria include waiting time, turnaround time and response time. First come first served, shortest job first, priority scheduling and round robin with a time quantum are common. A Gantt chart shows the order of execution.
Page replacement occurs on a page fault when no free frame exists. FIFO replaces the oldest page, LRU replaces the least recently used page, and the optimal algorithm replaces the page that will not be used for the longest time. Thrashing happens when a process spends more time paging than executing; the working set model prevents it.
Disk scheduling reduces head movement. SSTF selects the request closest to the head. SCAN moves the head end to end like an elevator and C-SCAN returns to the beginning without servicing requests.
